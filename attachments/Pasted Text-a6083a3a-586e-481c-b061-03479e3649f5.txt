Build a Lightweight Offline Pomodoro Timer Android App

Build a complete, production-quality Android Pomodoro / Focus Timer app with a strong emphasis on:

1. Extremely polished modern UI
2. Very lightweight APK size
3. Completely offline and independent
4. Highly reliable timer behavior
5. A major floating PiP-style Focus Widget that can remain above other apps
6. Excellent responsiveness and optimization on low-end as well as modern Android phones

The application must feel like a premium, minimal, modern productivity app rather than a generic timer.

---

1. Core Product

Create a Pomodoro timer application designed for focused studying, work and productivity.

The app must work 100% offline.

Do NOT require:

- Login
- Account creation
- Cloud database
- Backend
- Server
- API
- Internet connection
- Analytics
- Tracking
- Remote configuration
- Ads
- Third-party online services

All timer state, preferences and statistics must be stored locally on the device.

The app must remain fully functional with Wi-Fi and mobile data completely disabled.

2. Platform and Technical Direction

Build this as a native Android application.

Preferred stack:

- Kotlin
- Android SDK
- Native Android architecture
- Lightweight Android UI components
- Material components only where genuinely useful
- Android-compatible local persistence
- Coroutines only where necessary
- No unnecessary libraries

Prioritize APK size and runtime performance over dependency-heavy frameworks.

Avoid large libraries that do not provide substantial value.

Use:

- R8
- Resource shrinking
- Code shrinking
- APK optimization
- WebP/vector assets where appropriate
- Proper release optimization
- Minimize bundled fonts, icons, images and libraries

Target modern Android while maintaining broad device compatibility.

Recommended baseline:

- Minimum Android: Android 9 / API 28
- Modern Android versions must be properly supported
- UI must adapt to different screen sizes, densities and aspect ratios
- Support portrait and landscape where practical
- Do not assume a single phone resolution

The final release APK/AAB should be aggressively optimized.

Target:

- Ideal APK size: around 5 MB
- Excellent: under 10 MB
- Avoid unnecessary assets and dependencies

Do not sacrifice timer reliability or the floating widget merely to reduce APK size.

7. Mandatory Timer Controls

The timer must support:

Start

Starts the current session.

Pause

Pauses without losing elapsed/remaining time.

Resume

Continues from the exact paused position.

Restart

Restarts the current session from its configured duration.

Skip

Skips to the next configured session.

Time Selection

Allow users to change the session duration before starting.

Changing the duration while a session is running should be handled safely.

Do not accidentally reset the current session unless explicitly requested.

---

8. Timer Reliability

The timer is one of the most important components of the application.

Do NOT implement it as a naive UI-only decrementing counter.

The application must remain accurate when:

- Screen is locked
- App goes into background
- User switches apps
- Device is idle
- Floating widget is visible
- Activity is recreated
- Device rotates
- UI is temporarily destroyed/recreated
- System pauses normal rendering

Use time-based calculations based on reliable timestamps/monotonic timing rather than assuming the UI thread continuously executes every second.

The displayed countdown should be derived from actual elapsed time.

Avoid timer drift.

Example:

If the user starts a 25-minute timer and leaves the application for 5 minutes, the timer must still correctly represent approximately 20 minutes remaining when they return.

Do not force users into automatic transitions.

16. Floating Widget Performance

This is a TOP PRIORITY.

The floating widget must be extremely optimized.

Requirements:

- Very low CPU usage
- Minimal memory usage
- No unnecessary animations running continuously
- No high-frequency polling
- No battery-draining loops
- No constant expensive recomposition
- Avoid unnecessary redraws
- Pause visual work when not needed
- Use efficient time updates
- Reuse resources
- Keep widget rendering lightweight

The timer logic must remain accurate without requiring the widget to redraw every millisecond.

A practical display update frequency such as once per second is acceptable for the visible countdown while internally using precise elapsed-time calculations.

The widget must remain usable on lower-end Android devices.

17. Overlay Permission

Because the floating widget must appear above other applications, correctly implement the required Android overlay permission flow.

The application must:

1. Detect whether overlay permission is granted
2. Clearly explain why the permission is needed
3. Provide a button to open the correct Android settings page
4. Detect when the user returns
5. Re-check permission
6. Start the floating widget only after permission is actually available
7. Gracefully handle denial
8. Never crash because permission is denied

Do not request unrelated permissions.

Request only permissions genuinely required for the implemented features.

Use Android's proper overlay APIs and compatibility handling rather than hacks.

---

18. Background and Foreground Execution

The floating timer must continue reliably while the user is using other apps.

Use Android's supported mechanisms for user-visible long-running timer functionality.

Account for modern Android foreground-service restrictions.

Do not blindly assume background services can start at any time.

Ensure the service is started through valid user-initiated flows and is compatible with recent Android versions.

The application should explain to the user, when necessary, why the foreground service/overlay permission is required.

Keep the foreground service extremely lightweight.

Do not run unnecessary background work.

Do not force standard system PiP to behave like a freely resizable overlay if Android does not permit that behavior.

32. Single Source of Truth

The timer must have one authoritative state.

The following must always remain synchronized:

- Main timer screen
- Floating widget
- Notification
- Background timer state

Example:

If the user pauses the timer from the floating widget:

- Main app must show paused state when opened
- Notification must show paused state
- Timer must remain paused

If the user presses restart in the main application:

- Floating widget must immediately reflect the restarted timer

Do not implement separate independent timers.
